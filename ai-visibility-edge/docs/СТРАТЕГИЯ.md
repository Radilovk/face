## 1. Визия и крайна цел

### Визия

**Първият в България (и един от малкото глобално) възпроизводим индекс за AI видимост** — с контролна група, верифицирани цитати, разбивка по система (ChatGPT / Gemini / Perplexity) и ясно декларирани ограничения.

### Крайна цел (12–24 месеца)

1. **Секторен индекс** — публикуван, цитируем, финансиран от услуги и мониторинг.
2. **Платформа** — измерване + диагностика + edge поправка + консултиране по достъп.
3. **Исторически актив** — ≥4 седмици наблюдения по вертикал, включително control домейни, с пълен `raw_response` в D1.
4. **Собствени домейни** — живи демонстрации на всички три слоя.

### Какво НЕ е крайната цел

- Агенция „оптимизация за AI“ без данни.
- Един magic score без методология.
- Cloaking или различно съдържание за ботове.
- Обещание „№1 в ChatGPT след седмица“.

## 2. Проблем и възможност

### Проблем за клиента

Бизнесите не знаят:

- дали AI **вижда** сайта (корпус / индекс);
- дали AI **чете** съдържанието (техника);
- дали AI **цитира** при реални въпроси (извличане);
- дали цитатите са **верни** (атрибуция);
- дали отговорът идва от **кеш** (латентност);
- дали марката живее в **паметта** на модела без линк (параметрична памет).

### Възможност за нас

| Фактор | Защо сега |
|--------|-----------|
| AI търсене расте | Нов канал за откриване, различен от Google SEO |
| Няма стандарт | Клиентите и медиите търсят измерими индекси |
| Конвейерът е сложен | 10 слоя — нужна е система, не чеклист |
| Историята е ценна | Данни от ден нула не могат да се възстановят |
| Edge + измерване | Рядка комбинация: диагноза + поправка + корелация |

### Уникална позиция

```
Конкурент тип SEO агенция     → съвети без данни
Конкурент тип analytics SaaS  → метрики без поправка
Ние                           → измерване + диагноза + поправка + достъп + индекс
```

## 3. Какво строим — не само код

### Три продукта (слоя)

| Слой | Име | Изисква клиент? | Копируем? | Марж |
|------|-----|-----------------|-----------|------|
| 1 | **Измерване** | Не | Не (актив) | Данни → индекс |
| 2 | **Поправка** (edge) | Да (CNAME) | Да | Еднократно + абонамент |
| 3 | **Достъп** | Да | Частично | Висок, повтарящ се |

### Два незаменими актива

| Актив | Съдържание | Защо е ценен |
|-------|------------|--------------|
| **А** | Логове от **верифицирани** AI ботове + `content-version` | Корелация кеш ↔ жив сайт |
| **Б** | `runs` + `observations` + SOV + misattributions | История, индекс, делта |

**Правило:** Кодът може да се пренапише. Историята от наблюдения **не**.

### Три входа в системата

1. **Измерване** — въпроси към модели, вертикали, watched domains.
2. **Поправка** — KV фийд → HTML + JSON-LD + маркер за версия.
3. **Достъп** — правила кой бот чете как (бъдещ консултантски продукт).

### Продажбена последователност

```
Диагноза (Слой 1, безплатно) → Корекция (Слой 2, фикс) → Мониторинг (абонамент)
    → Кеш индекс (самостоятелно) → Достъп (Слой 3, консултиране)
    → Секторен индекс (публичен, цитируем)
```

## 4. Архитектура на системата

### Логическа схема

```
┌─────────────────────────────────────────────────────────────────┐
│                     ПОТОК НА ДАННИ                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  verticals + watched_domains (control/competitor)               │
│           ↓                                                     │
│  questions (manual + harvested + situational)                   │
│           ↓                                                     │
│  ask.js → adapters (openai, perplexity, gemini)                 │
│           ↓                                                     │
│  runs (raw_response, subquestions_detected)                     │
│           ↓                                                     │
│  verify.js (passage-level) → classify.js                        │
│           ↓                                                     │
│  observations + misattributions + sov_scores                    │
│                                                                 │
│  ─── паралелно ───                                              │
│                                                                 │
│  Edge Worker: config → enhance → botLog (verified only)         │
│           ↓                                                     │
│  Analytics Engine + content_versions                            │
│           ↓                                                     │
│  correlate.js + cache-index API                                 │
│                                                                 │
│  ─── продажба ───                                               │
│                                                                 │
│  diagnose/* → report PDF → клиент / prospect                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Физическа схема (Cloudflare)

| Ресурс | Binding | Роля |
|--------|---------|------|
| Worker | `ai-visibility-edge` | Router, hot path |
| D1 | `DB` | Tenants, runs, observations, SOV, diagnostics |
| KV | `CACHE` | Tenant config, feeds |
| R2 | `REPORTS` | PDF отчети |
| Queues | `DIAG_QUEUE` | Async probe, semantic verify |
| Analytics Engine | `BOT_HITS` | Verified bot hits |
| Browser Rendering | `BROWSER` | PDF |
| Cron | weekly | Citations cycle, drift detectors |

### Repo структура (целева)

```
ai-visibility-edge/
├── src/
│   ├── index.js
│   ├── middleware/       failOpen, timing
│   ├── config/           loader, schema
│   ├── verticals/        seed.js
│   ├── questions/        harvest.js
│   ├── citations/
│   │   ├── adapters/     openai, perplexity, gemini
│   │   ├── ask.js, verify.js, classify.js, correlate.js, reprocess.js
│   ├── diagnose/         probe, score, displacement, terminology,
│   │                       undiscoverable, consumer.js
│   ├── enhance/          inject, jsonld, contentVersion, robots, sitemap
│   ├── observe/          botLog, botList, verify.js
│   ├── index/            sov.js
│   ├── cache/            index.js
│   ├── drift/            access, retrieval, schema, config
│   ├── report/           template.js, pdf.js
│   └── admin/            api.js
├── migrations/           0001 … 0004
├── test/                 unit + guard тестове
├── content/              markdown → HTML (Фаза 0, собствени домейни)
├── wrangler.toml
└── docs/                 MASTER, СТРАТЕГИЯ, обяснение-за-всеки
```

### Правила за hot path (edge)

1. **Fail-open** — грешка или timeout (~50 ms) → оригинален отговор.
2. **Без блокиращ D1** — config от module cache / Cache API.
3. **Само HTMLRewriter** — никога `response.text()` на клиентски HTML.
4. **Идентичен HTML** за всички User-Agent — UA само за лог/диагностика на *чужи* домейни.
5. **Без PII** в логове.

## 5. Конвейерът и продуктовата карта

Между въпрос и цитат има 10 слоя (Механизмът). Таблицата връзва слой → диагноза → модул → оферта.

| Слой | Отпадане (опростено) | Модул в платформата | Поправка / оферта | Типичен срок |
|------|----------------------|---------------------|-------------------|--------------|
| 1 Корпус | Няма в Bing/Google индекс | `undiscoverable.js` (NOT_INDEXED) | Bing WMT, GSC, IndexNow | дни |
| 2 Извличане | 403, празен HTML | `probe.js`, enhance | robots, SSR, edge | часове–дни |
| 3 Пасажи | Несамостоятелни абзаци | `passage_autonomy`, verify по пасаж | content linter, структура | дни |
| 4 Търсене / термин | Грешни думи | `terminology.js` | език на пазара в текст | дни |
| 5 Подвъпроси | Няма покритие за тема | `harvest` situational, displacement | ново съдържание | седмици |
| 6 Reranking | Слаба позиция | displacement, SOV позиция | външни споменавания | месеци |
| 7 Приписване | Грешни цитати | verify, classify, misattributions | ясни числа, формули | дни |
| 8 Кеш | Остарял отговор | cache-index, correlate | синхрон с цикъл | дни |
| 9 Параметрична памет | Марка без линк | PARAMETRIC_RECALL (извън SOV) | присъствие, време | години |
| 10 Entity | Противоречива идентичност | probe (canonical, schema) | sameAs, консистентност | седмици |

**Отчетът** следва тази таблица — не generic „SEO score“.

## 6. Принципи и непроменливи правила

### Четири принципа (от Механизмът §16)

1. Машинно четимо, свежо, недвусмислено съдържание.
2. Разрешима идентичност (един обект).
3. Уникални проверими данни > преразказ.
4. Кеш → латентност → измерване.

Всичко, което не се извежда от тях → `platform_config` с `expires_at`, не hardcode в архитектурата.

### Затворени решения (не се преразглеждат без нов факт)

| # | Решение |
|---|---------|
| 1 | Измерване **преди** edge слой |
| 2 | Никакън branch по User-Agent за съдържание |
| 3 | Fail-open винаги |
| 4 | MISATTRIBUTED → отделен регистър, не 0 в SOV |
| 5 | Диференциална диагноза, не „shadow ban“ |
| 6 | Кеш индекс = разпределение + покритие |
| 7 | Control група във всеки вертикал (≥3 домейна) |
| 8 | Верни и проверими числа (здраве → Reg. 1924/2006) |
| 9 | PARAMETRIC_RECALL извън SOV |
| 10 | Custom Hostname, не пълен DNS |

### Правило за документи

**Нова идея → MASTER → СТРАТЕГИЯ → spec приложение.** Не обратно.

| Secret | Употреба |

## 8. Данни и активи

| Файл | Съдържание |
|------|------------|

### Ключови таблици

| Таблица | Роля |
|---------|------|
| `verticals` | Сектори (10–15), status, is_control |
| `watched_domains` | competitor / control / prospect / tenant |
| `questions` | source, intent, volume, situational |
| `runs` | **raw_response** (задължително), subquestions_detected |
| `observations` | class, passage fields, bot_verified |
| `misattributions` | търговски/здравен риск, извън SOV |
| `sov_scores` | по domain, vertical, **model**, period, formula_version |
| `platform_config` | ASN, ботове, прагове — с expires_at |

### Пет класове наблюдения

| Клас | Смисъл |
|------|--------|
| `GROUNDED_VERIFIED` | URL OK, силно съответствие |
| `GROUNDED_WEAK` | URL OK, слабо съответствие |
| `MISATTRIBUTED` | URL OK, твърдението не пасва → регистър |
| `FABRICATED_URL` | URL не съществува |
| `PARAMETRIC_RECALL` | Марка в прозата, не в citations |

### AI-SOV формула

```
SOV = 100 × Честота × Позиция × Интегритет

Интегритет: VERIFIED=1.0, WEAK=0.5
MISATTRIBUTED, FABRICATED → извън SOV
PARAMETRIC_RECALL → извън SOV, отделен ред в отчет
```

**В отчета:** разбивка по `model` — без осредняване.

## 9. Фази на изпълнение — блокове 0–7

### Общи правила за изпълнение

- Един **commit** на стъпка; acceptance минава → следваща стъпка.
- **Гейт** на блок = условие за преминаване; не се прескачат гейтове.
- Cursor / агент: spec приложения за acceptance детайли.
- **Блок 0.1** може да стартира **паралелно** с Блок 1 (ръчен запис на baseline).

---

### БЛОК 0 — Незаменимото (преди/паралелно с код)

**Цел:** Собствена демонстрация + базова линия за делта.

| ID | Задача | Deliverable | Отговор |
|----|--------|-------------|---------|
| 0.1 | **Базова линия** | 20 въпроса × 3 модела, пълен JSON API отговор, в git | Ти + API keys |

**Минимален cost (§18):** Започни с **5×3** (~$1–3 API); разшири до 20×3 в рамките на седмица. Ефективността на делта не се компрометира — само обхватът на baseline.

**Защо е блокиращо:** Блок 2 мери **делта** спрямо ден нула. Код може да се пише по-късно; записът не.

## 11. Методология на публичния индекс

За да издържа оспорване, публикуваният индекс **явно декларира:**

| Ограничение | Формулировка за публикация |
|-------------|----------------------------|
| Персонализация | Мерим **чисти сесии** — „непознат потребител“, не профил с история |
| Латентност | **Системна тенденция**, не прогноза за една страница |
| Покритие | Всяка стойност с **N наблюдения, M домейна, % покритие** |
| SOV | **По система** (OpenAI / Gemini / Perplexity), без осредняване |
| Формула | `formula_version` записан; промяна не преизчислява историята |
| Control | Ефект отделен от обща промяна в моделите |
| MISATTRIBUTED | Отделен риск регистър, не „липса на видимост“ |

## 17. Критични точки, моат и превенция

Тази секция обединява **системни предимства**, **вектори на срив** и **допълнителни рискове** — с фокус върху стратегически отговор, не само технически.

### 17.1 Системни предимства — как да станат моат

| Предимство | Риск да остане теория | Как го заключваме (минимален cost) |
|------------|----------------------|-------------------------------------|
| **Асиметрия на данните (Слой 1)** | Baseline не стартиран | `baseline/` в git **днес** (§18); cron само за пилот вертикал |
| **Контрол на достъпа (Слой 3)** | Строим код преди логове | Слой 3 = **playbook + отчет от логове** до първи клиент; код след Блок 4 |
| **Устойчивост (fail-open, no cloaking)** | Само в spec | Guard тестове в CI от Блок 1 — **безплатни**; canary = собствен домейн |

**Стратегическо правило:** Марж и моат към **Слой 1 + регистри (misattributions, cache-index) + Слой 3**. **Слой 2** = onboarding канал, не крайна печалба.

### 17.2 Вектори на срив — превръщане, не само отбягване

| Вектор | Стратегически отговор | Не компрометира ефективност, защото… |
|--------|----------------------|--------------------------------------|
| **Комодитизация (Слой 2)** | Планирай open-source на enhance при комодитизация; печалба от **корелация А×Б** и данни | Корелация изисква runs + bot hits — не се копира с плагин |
| **Затворени AI / параметрична памет** | **Belief audit** + `PARAMETRIC_RECALL` като продукт; SOV по model | Покрива сценарий „без линкове“ — не го игнорира |
| **Клиентски дисонанс** | Два раздела в отчета + карта слой→срок; продажба на Слой 1 първо | Намаля churn; не намаля обхват на измерване |
| **Времева критичност (0.1)** | MVP baseline 5×3 → разширение до 20×3; аларм „дни без run“ | Делта започва веднага; пълният обхват следва |

### 17.3 Допълнителни критични точки (могат да изскочат)

| Точка | Сигнал | Превенция (ниск cost) |
|-------|--------|-------------------------|
| **API разходи при скалиране** | Cron > budget | `platform_config` budget cap; 1 пилот вертикал; weekly не daily |
| **ToS / rate limits** | 429, account warning | Само официални API; jitter в probe; без UI scraping |
| **Малка извадка → фалшива прецизност** | SOV без N | Покритие + band в UI/API; не единично число |
| **Правен риск (misattributions)** | Здравни вертикали | severity; регистър на риска, не „медицински съвет“ |
| **Тихи пропуски в данни** | Липсващи седмици | Drift `config.js` + „дни без run“ в cron лог |
| **Копиране на методология** | Конкурент „същ индекс“ | Публичен агрегат; платен суров ред + control + история |
| **Bing→ChatGPT зависимост** | ChatGPT SOV = 0, Perplexity OK | Разбивка по model в отчет — вече задължително |
| **Cloudflare vendor lock** | Цени/лимити | D1 export; `raw_response` в git/R2 backup |
| **Parse drift на API** | Празни citations | FIXTURE тест + `reprocess.js` — без нови API calls |

### 17.4 Матрица: слой × сила × срив

```
Слой 1 Измерване   → СИЛНО: история, control     → СРИВ: 0.1, API cost
Слой 2 Поправка    → СИЛНО: trust, canary        → СРИВ: комодитизация
Слой 3 Достъп      → СИЛНО: bot economics        → СРИВ: платформи правят сами
Поперечно           → misattributions, methodology → parametric, dissonance
```

## 18. Минимални разходи без компромис с ефективността

**Принцип:** Не намаляваме **качеството на измерването** (raw, control, verify, passage). Намаляваме **обхват, честота и преждевременни услуги**.

### 18.1 Какво НЕ съкращаме (ефективността)

| Елемент | Защо е неприкосновено |
|---------|----------------------|
| Пълен `raw_response` в `runs` | Reprocess без нови API пари |
| ≥3 control домейна / пилот вертикал | Ефектът е научно отделим |
| Verify по пасаж + 5 класове | Качество на SOV и misattributions |
| Guard тестове (cloaking, PII, fail-open) | Един инцидент = край на препоръките |
| Разбивка SOV по model | Евтината поправка (Bing vs Google) |
| Два раздела в отчета | Предпазва churn и reputation |

### 18.2 Какво съкращаме (разход)

| Област | Пълен план | **Минимален план** | Спестяване |
|--------|------------|-------------------|------------|
| Baseline 0.1 | 20×3 веднага | **5×3 днес**, +15 следващата седмица | Време; делта започва |
| Вертикали | 15 от ден 1 | **1 пилот** + 2 леко; +12 след Блок 3 | ~80% API в началото |
| Въпроси / вертикал | 30+ harvested | **20 ръчни** + шаблони situational | Без Ahrefs |
| Cron citations | 3× всички въпроси weekly | **3× 10 core въпроса** weekly; rest biweekly | ~50% API |
| Модели | 3 винаги | **2 модела** ако един няма citations (spec gate) | ~33% |
| Semantic verify (Queue) | Всички weak cases | Само **MISATTRIBUTED-suspect** + sync numeric първо | CPU + queue |
| Cloudflare | Paid от ден 1 | **Free + local D1** до canary; Paid при CNAME клиент | $0 до клиент |
| Browser Rendering PDF | Всеки отчет | HTML отчет **по подразбиране**; PDF при sales-ready | Rendering fees |
| Displacement в диагностика | 8 въпроса | **3 въпроса** за безплатен lead; 8 за платен | API при prospecting |
| IndexNow | Всички tenants | Само **canary + платени** | Ниско, но контролирано |

### 18.3 Ориентировъчен бюджет (пилот фаза)

| Позиция | Минимален режим | Бележка |
|---------|-----------------|---------|
| Cloudflare | $0 (Free tier) | Workers Paid ~$5/мес. при edge клиент |
| OpenAI | $15–40/мес. | Cap в dashboard; Responses + search по-скъпи |
| Perplexity | $20/мес. plan или API paygo | Често най-евтин за citations тест |
| Gemini | Free tier API | Достатъчен за пилот с rate limits |
| Ahrefs | **$0** | Не в MVP |
| **Общо пилот** | **~$20–60/мес.** | Преди клиенти; не $500+ „пълен индекс“ |

**Hard cap:** `platform_config` ключ `api_budget_monthly_eur` — cron спира, не тихо продължава.

### 18.4 Безплатни заместители със същата ефективност

| Нужда | Пълен вариант | **Безплатен вариант** |
|------|---------------|----------------------|
| Въпроси от интент | Ahrefs + GSC API | Ръчни 20 + PAA ръчно + Google autocomplete |
| Baseline | Автоматизиран cron | Ръчен JSON в git → `import-baseline.js` |
| PDF отчет | Browser Rendering | HTML + print CSS; PDF при нужда |
| Dev / тестове | Cloud deploy | `wrangler dev` + D1 local |
| Bot логове | Analytics Engine | Mock в тестове; AE само на canary |
| Диагностика probe | 50 домейна batch | 10 домейна за MVP gate |
| Регресия адаптери | Live API всеки cron | FIXTURE parse **всеки** deploy — $0 |

### 18.5 Ред на разходите (когато има приход)

```
1. API за пилот вертикал (данни)
2. Workers Paid (edge клиент)
3. Разширение вертикали (+1 на месец, не +10)
4. Browser Rendering (ако клиент иска PDF)
5. Ahrefs (само ако harvest не покрива с ръчно)
```

**Не купувай преди гейт:** Paid CF преди canary; 15 вертикала преди 4 седмици пилот; PDF преди първи платен отчет.

### 18.6 Ефективност чрез архитектура (един път код, многократна полза)

| Механизъм | Ефект | Разход |
|-----------|-------|--------|
| `reprocess.js` | Поправен parser без нови API | $0 |

| FIXTURE в CI | Parse drift преди production | $0 |
| Import baseline от git | Блок 2 без чакане на cron | $0 |
| Regex `passage_autonomy` | Диагностика без embedding API | $0 |
| Sync verify (numeric) | По-малко Queue semantic jobs | По-малко CPU |
| Control група в seed | Не изисква допълнителни API calls | Същият cron, по-силен индекс |
